# Methodology Release — 1.2.0 (2026-07-18)

## Metadata

- **Version:** 1.2.0 (SemVer)
- **Released:** 2026-07-18
- **Previous version:** 1.1.0
- **Bump level:** minor

## Summary

Sharpens judgment and publication boundaries. This release gives adopters clearer tests for how
much process a slice earns, how a safety boundary should fail, when to open a GitHub issue, and what
belongs on the public method surface. Existing 1.1.0 workflows remain valid.

## Highlights

- New judgment compasses: hygiene vs program closeout, and fail-open vs fail-closed boundary design.
- New public `github-issue-promote` skill: issues are optional visibility, not a second source of
  truth, and labels are mandatory at creation.
- Plan incubation now distinguishes an ephemeral scaffold from a retained working plan.
- The public method is an explicitly curated subset; operational skills stay private by default.
- The methodology rich view now reflects all of the above.

## Breaking changes

None. Existing 1.1.0 workflows remain valid.

## Added

- Public decision on classifying **hygiene vs program** closeout, so lightweight passes take a
  commit or PR and targeted docs while only program slices earn `I-*`, `TB-*`, and traceability.
- Public decision on the **fail-open vs fail-closed** design compass for critical boundaries.
- Public decision on the **ephemeral scaffold vs retained working plan** distinction for plan
  incubation.
- Public decision on curating the **public skills corpus explicitly** through one allowlist.
- Public `github-issue-promote` skill and its entry in the rich view skills table.
- New "Judgment Compasses" section in the methodology rich view.

## Changed

- `minimum-viable-method.md` and related surfaces express hygiene as a proportional closeout choice,
  not a workflow lane.
- `github-issues-workflow.md` clarifies that promotion creates a labeled issue on explicit request,
  with product-docs canon remaining the decision of record.
- Plan incubation guidance requires classifying a plan as ephemeral or retained before claiming
  bidirectional traceability.
- The public skills layer is now a deliberate, allowlisted subset rather than automatic discovery.

## Fixed

- Removed incorrect "Lane C" labeling of hygiene work across method surfaces (Lane C remains legacy
  retrofit).
- Public methodology pages no longer link into non-published source-project surfaces.

Adopters of 1.1.0 need no migration. Use the new compasses and the `github-issue-promote` skill only
where they reduce a concrete risk or add real visibility.
