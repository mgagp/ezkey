# Methodology Release — 1.1.0 (2026-06-04)

## Metadata

- **Version:** 1.1.0 (SemVer)
- **Released:** 2026-06-04
- **Previous version:** 1.0.0
- **Bump level:** minor

## Summary

Adds release-management guidance and strengthens the methodology's repository-native operating
model. This release gives adopters a lightweight way to scope Evergreen releases, preserve release
readiness evidence, calibrate methodology weight, and keep artifact review traceable without adding
unnecessary ceremony.

## Highlights

- New Evergreen release-management workflow and `release-brief` template.
- Repository-native artifact identity and review guidance: trackers and branches remain optional
  coordination layers, not the source of product reasoning.
- Minimum Viable Method now includes method-weight calibration and artifact aging guidance.
- Methodology releases are now anchored by annotated Git tags such as `methodology/v1.1.0`.

## Breaking changes

None. Existing 1.0.0 workflows remain valid.

## Added

- `release-management-workflow.md` for lightweight Evergreen release readiness.
- `release-brief.template.md` for release scope, stabilization, publication evidence, and patch
  forward-port tracking.
- `artifact-identity-and-review.md` for repository-native artifact identity and review attribution.
- Public methodology decisions covering release Git tags, repository-native review, calibration and
  aging, and Evergreen release management.

## Changed

- `minimum-viable-method.md` now helps adopters choose the smallest appropriate artifact set and
  periodically reclassify stale artifacts.
- `nomenclature.md` now explains the coordination purpose of date-and-slug identifiers.
- `methodology-publication-and-versioning.md` and the `methodology-release` skill now use
  `methodology/v*` tags as release anchors.
- Methodology and template indexes now expose the new release-management and review surfaces.

## Fixed

None in this release.
