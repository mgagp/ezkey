## Rationale (short)

### 1 - SQL-ISO-001

Operator **GO** (`fix`) 2026-09-15. Use of a foreign enrollment stays fail-closed (no 201, no
Tenant B names). The defect is the **client dialect** after unscoped `findById`: missing vs
other-integration currently return distinct RFC 9457 `detail` strings (and Springdoc still
advertises a 403 belong-message that live Path 1 does not use). Authorized remediationshape:
one client Problem for both outcomes (default keep HTTP 400 + generic detail; 404
`resource-not-found` also authorized). Do not echo the enrollment id. Keep server WARN. Keep
own-integration inactive as 403. No code in the assessment session (operator did not say
implement now).

### 2 - SQL-ISO-002

Operator **GO** (`fix`) 2026-09-15. Tenant Admin cannot read Global Admin **contents** (403
body has no username). The defect is the **existence dialect**: GET GA id 403 vs unused id
404 (PATCH foreign is 400 via the same `getAdminById` IAE). Authorized remediationshape:
hide-existence 404 + `admin/resource-not-found` for missing, other-tenant, and GA
(`tenant=null`). PATCH foreign follows. List SQL unchanged. Onboarding 400 stays a related
peel. No code in the assessment session (operator did not say implement now).

### 3 - SQL-ISO-003

Operator **GO** (`fix`) 2026-09-15. Global uniqueness stays (login key). The defect is the
**client dialect** on Tenant Admin peer-create: 400 `Username already exists: admin.docker`.
Authorized remediationshape: generic HTTP 400 detail (no “already exists”, no echoed
identifier); log the collision server-side; align the unique-constraint race path. Honest
limit: 400 vs 201 on a valid payload still signals that the name is taken. Out of GO:
per-tenant usernames; reserved GA namespace. No code in the assessment session (operator
did not say implement now).
