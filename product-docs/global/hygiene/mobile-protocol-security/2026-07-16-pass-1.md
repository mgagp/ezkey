## Rationale (short)

### 1 - MOB-001

Highest claim-integrity risk for an authentication product. Default hygiene path is wording lockdown;
CryptoObject is the durable fix but is a program slice needing a physical phone. The operator
selected Track A on 2026-07-18; living copy and documentation were aligned without changing the
native key model.

### 2 - MOB-002

Clear lifecycle bug: delete API exists, wipe paths ignore it. Cheap hygiene fix with unit tests;
optional instrumentation.

### 3 - MOB-004

Pilot/QA logcat leakage of enrollment proof material. Low cost, high hygiene value for a security app.

### 4 - MOB-007

Maintainability risk that becomes security drift. Shared helper keeps fail-closed pending verify consistent.

### 5 - MOB-006

Without native tests, Keystore/StrongBox regressions are invisible. Emulator covers basics; StrongBox needs a phone.

### 6 - MOB-008

Docs pointing at wrong packages waste cold-agent time and can cause wrong fixes. Docs-only.
