## Follow-up RCA (PR #1534 checkout)

### Scope

This follow-up fixes the `containers.secretsInRawLogs` RED caused by a false positive on:
`Pending administrator activated: e2e-<...>`.

`jm.integration-api.httpErrorPct` is intentionally left unchanged in this slice (separate engineering
review needed for concurrent cancel semantics and health scoring strategy).

### Root cause

1. Production logging emits `Pending administrator activated: <username>` in
   `AdminProvisioningService` (introduced in merged commit `51cd476da`, PR #1152).
2. The secrets scanner only recognized username glue contexts such as `Tenant admin created:` and
   `pending admin ` from commit `bb84f081a` (PR #1414).
3. Because `Pending administrator activated: ` was missing from
   `isAdminUsernameOpaqueContext`, a test-generated username matched the opaque-token rule and was
   scored RED.

### Applied fix

- Extend `isAdminUsernameOpaqueContext` in `scripts/lib/quality-gate-secrets.mjs` to include
  `Pending administrator activated: ` as an exact label context.
- Keep fail-closed behavior intact: only known test-username shapes can downgrade to AMBER.

### Proof tests

- `node scripts/lib/quality-gate-secrets.test.mjs` → **pass** (108/108).
- Added focused regression tests:
  - negative: activation line + known test-admin username shape => AMBER `opaque-username`.
  - positive: same activation line + realistic opaque secret => RED `opaque-token`.

This proves the fix addresses the specific false positive without weakening opaque-secret detection.
