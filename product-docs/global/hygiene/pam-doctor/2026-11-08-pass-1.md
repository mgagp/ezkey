## Context

### 1 — cppcheck `doubleFree` (suppressed, code restored)

cppcheck 2.13 reports `fd` freed twice at `ezkey_filelog_append` and `load_config_file`. Both sites are the POSIX pattern: `close` only when `fdopen` fails, `fclose` only when it succeeds. The tool does not model that transfer. It stays silent on the exclusive early `close`s in `ezkey_diag.c`.

A sentinel `fd = -1` was tried so a later `close(fd)` would hit `EBADF`. cppcheck still reported `doubleFree`, and clang-tidy called the sentinel a dead store, so the code grew a `(void)fd` and an inline suppression. That is tool appeasement. The behavior never changed. The sentinel is removed. The source is the POSIX pattern again.

The exception lives in `config/pam-doctor/suppressions.json`, one entry per file. The `pam_ezkey.c` entry is wider than `load_config_file`, because the curator filters on path only. A new `doubleFree` in that file reopens the entry.

### 2 — `planned_wait` stored and never read (fixed)

When the create response carries a numeric `timeoutSeconds` (else `ttlSeconds`) inside `1 .. planned_wait`, that value is cast to `applied_ttl` and published. The following store `planned_wait = applied_ttl` was never read. It is removed. The cap comparison against `planned_wait` stays, so an out-of-range or missing TTL still keeps the planned value. Re-run: no `DeadStores` remain. `test-budget` still pins `ezkey_planned_wait_from_rem`. No new case: the published value did not change.

### 3 — `cert-err33-c` (dropped from the narrow set)

Forty warnings, almost all `snprintf` into a sized stack buffer, plus `fprintf` / `fclose` on the log and conf paths. clang-tidy’s own note is “cast to void”. Those casts would be the pattern later edits copy. `cert-err33-c` is disabled in `ezkey-pam/.clang-tidy`. The other `cert-*` checks stay.

### 4 — Google clang-format baseline (applied)

`clang-format -i` on `ezkey-pam/src` with the Google preset (18.1.3). Seventeen files. The re-run reports zero format diffs. `make check-source` still matches the statement-form guards. `make test` on Ubuntu 24.04 (the CI package set) passed: compile, hardening, and the harnesses. The `/dev/log` case in the diag harness skipped, as it does on a host without a syslog socket. No new test.

### 5 — `EZKEY_HTTP_BODY_MAX` (fixed)

The macro is now `((size_t)64 * 1024)`, so the multiply is in `size_t` and the value stays 65536. Re-run: the widening warning is gone. `make test-http` passed, including the exact-cap assertion. No new test.

### 6 — repeated cancel-status branch (suppressed)

Empty or missing cancel tokens, and tokens outside the four known values, both become `EZKEY_CANCEL_SKIPPED`. Those are two reasons for one outcome. Merging them would hide the distinction. The branches stay. `bugprone-branch-clone` is suppressed for `ezkey_diag.c`. A new clone in that file reopens the entry. `test-diag` already covers the attempt line. No new test.
