## What ran

One Docker replay. Baseline `make test` first (production flags, including `check-source` and `check-hardening`). Then the nine C harnesses rebuilt with AddressSanitizer and UndefinedBehaviorSanitizer together. Then the same nine harnesses again, on a separate non-sanitized `-g` build, under Valgrind Memcheck. ASan and Valgrind were not combined.

Sanitizer compile flags (fortify off on that build only, because fortify and ASan wrap the same libc calls):

`-O1 -g -fno-omit-frame-pointer -fsanitize=address,undefined -fno-sanitize-recover=address,undefined -U_FORTIFY_SOURCE -D_FORTIFY_SOURCE=0`

plus the Makefile's `-Wall -Wextra -std=c99 -D_POSIX_C_SOURCE=200809L -fstack-protector-strong`. Runtime: `ASAN_OPTIONS=detect_leaks=1:halt_on_error=1:abort_on_error=1` and `UBSAN_OPTIONS=halt_on_error=1:abort_on_error=1:print_stacktrace=1`.

Valgrind: `--leak-check=full --show-leak-kinds=definite,indirect --errors-for-leak-kinds=definite,indirect --track-origins=yes --error-exitcode=99`. Still-reachable blocks do not fail the run. The container is started with `SYS_PTRACE` and `seccomp=unconfined` so LeakSanitizer and Memcheck can attach.

`make test` itself is unchanged when `EZKEY_TEST_WRAPPER` is empty. The wrapper is how Valgrind prefixes the existing harness binaries, including `test/run-filelog-harness.sh`.

## Observed and not retained

### Forked `test-http` children

Valgrind follows `fork`. The stub children in `test-http` call `_exit` while the parent still holds libcurl. Each child reports 168,901 bytes still reachable in 2,675 blocks, with **0 definite** and **0 indirect**. The parent (pid of the Memcheck command) ends with `All heap blocks were freed -- no leaks are possible` and `ERROR SUMMARY: 0`. Still-reachable on those children is the inherited heap, not a product leak. Not a lot item.

### `/dev/log` in `test-diag`

`[SKIP] T2/N1: /dev/log open failed` on this image, which has no syslog socket. Same skip as pass-1. The harness still passed. Not a sanitizer finding.
