## Rationale (short)

### 1 - CTRL-ROLE-001

Operator chose **fix**. Auth API bind stays token-gated (no tenant filter). The defect is Admin
API QR distributing the bind handle (`id` + proof token) to a Tenant Admin who already gets
403 on JSON GET. Harm is consumption of a pending invite (`CREATED` → `BOUND`), not automatic
MFA takeover (challenge is a second envelope; wrong verify burns the row). Human walkthrough
and sequence diagrams live in the assessment register.

**Closeout 2026-08-19:** `getQrCode` calls `canAccessEnrollment` and denies with HTTP 404.
Coverage: `EnrollmentControllerQrAccessTest` plus `TenantCrossIsolationSecurityTest` QR
deny/own-tenant rows; live stack confirmed 404 for a foreign Tenant Admin and 200 for an
own-tenant CREATED invite. Ephemeral handoff deleted.
PR: [#470](https://github.com/mgagp/ezkey/pull/470). JSON GET remaining 403s stay with 003b.

### 2 - CTRL-ROLE-002

Operator chose **fix**. Durable controller convention: `ROLE_ADMIN` means any authenticated
admin, not tenant isolation and not Global-only. Function split uses `GLOBAL_ADMIN` /
`TENANT_ADMIN`; object split uses `AccessControlService` (or equivalent). Greenfield would
drop the `ROLE_ADMIN` umbrella and annotate `hasAnyRole(GLOBAL, TENANT)` vs
`hasRole(GLOBAL)` — that is honesty, not a substitute for object checks. Mass annotation
rewrite is optional in the same handoff, not required to close the class.

**Closeout 2026-08-20:** convention written in `ezkey-admin-api/AGENTS.md` § Authorization
at controllers. No Java annotation migration. Ephemeral handoff deleted.

**002b settled 2026-08-20 (operator accepted unified analysis):** Path A — keep
issuing `ROLE_ADMIN`. Do not drop the umbrella. Annotation honesty is optional later
hygiene, not isolation. Filter cutover is not funded. Ephemeral 002b handoff deleted.
