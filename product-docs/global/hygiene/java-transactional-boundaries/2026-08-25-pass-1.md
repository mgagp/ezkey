exception. `NOT_SUPPORTED` wait plus a cross-bean `REQUIRES_NEW` create is how the proxy rule
is *honored*, not broken. Do not analogize that pattern onto schedulers or CRUD.

Operator **GO** (2026-08-25): honest annotations only. Keep `@Transactional` on scheduler /
HTTP entry points; drop or document dead inner annotations on `this` calls. Class split and
per-key `REQUIRES_NEW` are out of this GO. Existing `KeyRotationServiceIntegrationTest` is
enough. Implemented on this branch.

### 2 - TX-002

with `@Transactional` (F-001 pattern). Remove `@Transactional` from `@PostConstruct`. Keep
fail-open on sync failure. Slim TX-active test; no Tink re-test. Same-PR with TX-001 optional.

### 3 - TX-003

`processReencryptionBatches`. Do not add `NOT_SUPPORTED`. Collaborator `REQUIRES_NEW` stays.
Existing re-encryption tests only.

### 4 - TX-004

one-line Javadoc that only the public entry applies. No new test. F-002 closed by this GO.
