## Rationale (short)

### 1 — Hydration callbacks ref — **defer**

The hook comment says the ref exists so callback identity churn does not double-fetch chain and
entry reports. React Doctor’s error is real as a rule (render may be discarded) and weak as a
defect: the assignment is the current render’s callbacks, and effects run only for a committed
render. A “fix” that assigns the ref in `useEffect` is easy to order wrong next to the hydration
effect. Leave it.

### 2 — Adjust state when props change — **defer**

Nine warnings, one pattern: an effect resets or opens UI when a prop, job status, or URL signal
arrives. That costs a render. It is how the integrity atelier, the batch-health collapse, and the
pending-attempt draft stay aligned with server state. The micro-dashboard poll pair is the one
site that must not be “simplified”: poll errors are visible on purpose (#788).

### 3 — Native dialog — **defer** (known program)

Same four surfaces as 2026-07-15 (shared `Dialog` plus help, timezone, context-help). Focus trap
and Escape are already implemented in the shell. Migration stays
`I-2026-07-14-admin-ui-native-html-dialog`.

### 4 — `transition-all` — **hygiene fix**

Two class names. The progress bar only animates width. The dashboard quick-action link animates
border, shadow, and background on hover; naming those properties keeps the hover and drops layout
animation. Modest allotment, no design change.

### 5 — Object URL helper — **defer**

QR blob URLs are revoked in the two call sites’ cleanups. The diagnostic cannot see callers from
inside `fetchBlobUrl`.

### 6 — Ref init and reconcile latch — **defer**

Micro-optimizations on integrity surfaces. `autoReconcileConsumed` is a one-shot guard, not unused
state. Do not trade it for another render-time ref write.

### 7 — Reappearing P2 stock — **defer**

Pass-1 already skipped Set/Map rewrites on operator-sized lists and the audit-log URL effect.
The `includes` sites moved onto the integrity reconcile dialog; the lists are still the ack
checkboxes for one rupture, not a large scan.

### 8 — Login wait after await — **Christophe**

Session establishment on the cookie build is a security boundary. The missing signal is only on
the follow-up `GET /me`, after the device wait has already succeeded. Scope any change to “ignore
a stale completion,” not a redesign of passwordless wait.
