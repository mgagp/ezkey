## Rationale (short)

### 1 - TINK-DEP-001

Confirmed by compiler deprecation warning in Tink 1.23.0. Replacement is straightforward and behavior-preserving (explicit configuration path).

### 2 - TINK-DEP-002

Wider footprint than item 1 (rotation/add/promote/info reads), still an internal call-shape migration. Needs careful characterization because key ID extraction is central to rotation logic.

### 3 - TINK-DEP-003

The original quick pass deferred this because the `KeysetHandle` encrypted IO replacements were not
visible from the first local check. Follow-up inspection found the public, non-deprecated,
configuration-aware `TinkJsonProtoKeysetFormat` encrypted-keyset APIs. The implementation keeps the
file representation as an encrypted JSON keyset and preserves the current master-AEAD model.

This closes the deprecation pressure for the keyset persistence path without forcing a broader
storage redesign. The database `KeysetBlob` path still uses Ezkey's existing outer
`masterAead.encrypt(cleartextJson)` envelope, but the JSON keyset codec is now non-deprecated. A
future PoC may still consider replacing that DB envelope with Tink's encrypted-keyset envelope, but
that is a separate design choice rather than a blocker for this hygiene item.
