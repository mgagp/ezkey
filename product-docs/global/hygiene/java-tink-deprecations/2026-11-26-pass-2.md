## Micro-studies per deprecated API

### TINK-DEP-004 — `KeysetHandle.generateNew(KeyTemplate)` (deprecated)

- **Where observed:** production and test code in `ezkey-core-security`.
- **Library guidance read from Tink source (1.24.0):**
  - deprecation says to inline toward parameters-based generation.
  - recommended transition is `KeysetHandle.generateNew(keyTemplate.toParameters(), RegistryConfiguration.get())`.
- **Risk focus:** key-id generation path and primary-key semantics during bootstrap/rotation.
- **Decision:** **fix** (apply named recommended transition exactly).
- **Implementation:** replaced all affected call sites in manager + characterization tests.

### TINK-DEP-005 — `KeysetHandle.getKeysetInfo()` (deprecated)

- **Where observed:** characterization test path in `KeysetBlobOnlyInvariantTest`.
- **Library guidance read from Tink source (1.24.0):**
  - deprecation warns this path can throw serialization-related errors and suggests richer access via
    `getPrimary()/getAt(i)` and key parameters.
- **Risk focus:** selecting the pending key deterministically without relying on deprecated metadata
  serialization path.
- **Decision:** **fix** (replace test lookup logic with `getAt(i).getId()` iteration).
- **Implementation:** replaced key-discovery logic with direct key-handle iteration.
