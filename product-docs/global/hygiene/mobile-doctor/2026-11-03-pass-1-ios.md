## Rationale (short)

### 1 — `EZK_VERIFY_ERROR`

iOS `verify` never rejects by design (false on malformed input; XCTest
`testVerifyNeverRejectsOnMalformedInput`). Android's `EZK_VERIFY_ERROR` branches are effectively
unreachable too: `IntegrationKeyVerifier.verify` already catches everything and returns false. Both
fail closed. The constant keeps the iOS `EZK_*` table identical to Android's, as the docs promise.
Removing it would buy nothing in working crypto code.

### 2 — `isLowS` / `flipS`

Test helpers for the low-S arithmetic: `isLowS` checks the n/2 boundary and real signatures (5
assertions), and `flipS` builds the high-S malleability case. Periphery does not count the
`@testable` test target as a caller. Moving them to the test target would mean exposing the
codec's private arithmetic. Counting tests as roots in Periphery was rejected: it would hide real
dead code that only a test still calls.

### 3 — `securityLevel`

Vestigial on both platforms: Android also ignores it (StrongBox first, then fallback); the only JS
caller (`cryptoService.ts`) does not pass it; the user security preference applies at approval
time (`usePendingAuth.ts`). Parity holds. A cross-platform bridge cleanup (TS + Kotlin + Swift +
Objective-C extern) was left out: zero behavior change for two native CI runs.

### 4 — Bridge and template signatures

`@escaping` on React Native promise blocks is the convention, and some methods call them
asynchronously (`signWithAuthentication`). Methods that never fail still need the resolve/reject
pair. `AppDelegate` / `SceneDelegate` parameters and optional collections are imposed by UIKit and
the RN 0.88.1 template. `infoDictionary` mirrors `Bundle.infoDictionary`. The `unused_parameter`
suppression on the module is scoped to `'reject'`, so a future truly unused parameter still shows.

### 5 — Tests

The two `throws` were superfluous (no `try` in the body): fixed, the low-signal allotment. The IUO
fixture is the XCTest setUp/tearDown idiom; `NSDictionary` is needed to compare
`[AnyHashable: Any]`.
