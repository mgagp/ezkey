## Rationale (short)

### 1 — Gradle space-assignment (listing warnings) — **fixed**

Cloud probe with `--warning-mode all` reproduced Groovy DSL space-assignment deprecations
scheduled for removal in Gradle 10. Justin’s F dump confirmed the same warnings are
**app-owned** under `ezkey_mobile/android/app/build.gradle` (ignore RN/`node_modules` Gradle).
Marc GO 2026-09-17: rewrite assignment syntax only for `ndkVersion`, `buildConfig`, `namespace`,
`signingConfig` (debug + both release branches), and `shrinkResources`. No other hygiene items.

### 2 — `js-set-map-lookups` — **fixed**

`expandedInstallations.includes(group.installation.id)` inside the installation-group map was a
classic O(n²) micro-smell. Marc GO 2026-09-17: keep `string[]` state (toggle / effect unchanged);
derive `expandedInstallationIds = useMemo(() => new Set(expandedInstallations), …)` and use
`.has` in the map. Same pattern as existing `brokenIds`.

### 3 — `rerender-lazy-state-init` — **fixed**

`useState(normalizeLocale(...))` re-evaluated the initializer every render (result discarded after
first mount). A brief **skip** was recorded when the HITL widget went unanswered; Marc then
**GO fix now** (2026-09-17), overriding that skip. Implemented:
`useState(() => normalizeLocale(...))`. No i18n/UX behavior change.

### 4 — DangerZone FlatList pair — **fixed**

Doctor flagged inline `renderItem` and rebuilt row `onPress`. Marc GO 2026-09-17 (local only):
extract same-file `DangerZoneEnrollmentRow` (`React.memo` + `useCallback` `handlePress`) and
`renderEnrollmentItem` useCallback. UI unchanged; no shared list-pattern / Patrick-scale redesign.

### 5 — Crypto unused symbols — awaiting HITL

`generateEnrollmentKeyPair(..., securityLevel: String?)` currently ignores `securityLevel`
(Javadoc says unknown/null falls back). Constant
`SECURITY_LEVEL_CONFIRM_BEFORE_APPROVALS` is unused. Diagnosis is clear; rewriting crypto bridge
for Detekt cleanliness is the wrong trade. **Proposed: defer → Christophe.**

### 6 — Play fail-open catches — awaiting HITL

`EzkeyPlayUpdateModule` intentionally catches broad `Exception` and resolves “no update” so
enrollment / auth stay unblocked. Aligns with fail-open product posture. Do not “narrow” catches
without a Play SDK exception map and device evidence. **Proposed: defer.**
