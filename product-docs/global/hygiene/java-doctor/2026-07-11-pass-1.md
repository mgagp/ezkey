## Rationale (short)

### 1 — RCN redundant nullcheck

SpotBugs line numbers pointed at class / Javadoc, not a clear `if`. Fuzzy signal rule: do not open
bytecode to invent a defect. Skip.

### 2 — TinkKeyManager useless condition (dig 2026-07-11 → suppress)

SpotBugs LongMessage localizes **without bytecode**:

1. **`normalizePath`**: inside `path.length() >= 3`, ternary `path.length() > 2 ? …` is always true.
2. **`toUnsignedLong(long)`**: after negative branch, `<= Integer.MAX_VALUE` is always true.

Operator decision **C**: leave as-is. Harmless over-defense; redundancy is obvious within ~3–4
lines. No pragmatic gain from rewriting; would force extra test work for zero product value.
Method lesson: clear diagnosis ≠ obligation to change code (if it ain't broken, don't fix it).
Suppress `UC_USELESS_CONDITION` for `TinkKeyManager`.

### 3 — EncryptionEntityListener static write

Documented intentional pattern (JPA listeners are not Spring-managed). Tool correctly flags; posture
is accept + suppress with reason.

### 4 — AuditHmacService SecureRandom once

One-shot HMAC keyfile generation at first startup — not a hot path. Design is satisfactory; suppress
rather than churn crypto bootstrap for SpotBugs style.

### 5 — AdminAuthService.logout empty catch

Comment claimed logging but catch was empty. Logout must remain best-effort (no API failure). Option
A: warn-level log with exception, no sensitive token material in the message.

### 6 — UnusedLocalVariable

`requestAuditDetails` was computed before the try and never read — leftover from earlier audit-log
evolution cycles. Success and failure paths each rebuild event details. Removed the dead line.
