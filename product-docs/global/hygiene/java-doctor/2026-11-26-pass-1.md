## Rationale (short)

### 1–2 — Tink deprecations (defer)

These calls are in crypto/keyset-sensitive areas. The migration is likely feasible but should be
done in one controlled pass with characterization tests to preserve key lifecycle behavior.

### 3 — `HttpStatus.PAYLOAD_TOO_LARGE` (fix)

Multiple production call sites plus one test assertion, straightforward replacement path, and low
functional risk. Good quick win to reduce warning volume quickly.

### 4 — `Level.ALL` in one test (fix)

Local test-only change with low blast radius; can be done after the HTTP status quick wins.

### 5 — `JsonNode.asText(String)` (fix)

Single test utility call site; easy migration and low risk.

### 6 — Explicit `H2Dialect` warning (fix)

Hibernate now warns that explicit H2 dialect setting is unnecessary in this context. Test config
cleanup with very low product risk.

### 7 — Spotless/Unsafe warning (defer)

This warning is emitted from formatting tooling internals, not Ezkey application code. It should
be handled through toolchain maintenance, not product module refactoring.
