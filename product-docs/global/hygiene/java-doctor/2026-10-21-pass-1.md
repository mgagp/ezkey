## Rationale (short)

### 1 — BootstrapCredentialsFileExporter stale primitive write — **hygiene fix**

SpotBugs `mt_correctness` on a non-volatile `boolean` updated during atomic write /
POSIX fallback and read for INFO strings. Impact is **log/mode accuracy**, not crypto
correctness. Cheap visibility fix is proportionate; keep recovery-code fail-closed paths
untouched.

### 2 — IntegrityAsyncJobBusyException SE_BAD_FIELD — **defer**

`RuntimeException` + non-serializable payload is common API busy signaling. No evidence
these exceptions are Java-serialized. Reworking the 409 contract for SpotBugs is accidental
complexity.

### 3 — EzkeyCoreProperties ISC — **defer**

`new Crypto()` is the normal `@ConfigurationProperties` nested-object pattern. Suppress only
if the curator keeps elevating it as P1 noise.

### 4–5 — RCN / throws families — **defer** (known)

Pass-1 already skipped RCN as fuzzy and parked throws-clause noise. Biweekly rotation does
not reopen that campaign.

### 6 — CT_CONSTRUCTOR_THROW — **Christophe**

Encryption / Tink construction throwing on misconfiguration is a fail-closed boundary
(`design-principles` §17). Flag for security owner awareness; do not hygiene-rewrite.

### 7 / 9 — Vacuous instanceof + Locale convert — **hygiene fix**

Strong signal-to-effort; suitable for a later small hygiene PR without redesign.

### 8 / 10 — Null-path / catch / cast style — **defer**

Curator P2 volume without a clear defect. Follow “if it ain’t broken, don’t fix it.”

### 11 — Entity overridable ctor calls — **Patrick**

Entity lifecycle craft; not Fred’s punctual polish.

### 12 — TinkKeyManager dead store — **Christophe**

Same security-sensitive zone as pass-1 Tink suppressions; no autonomous delete.
