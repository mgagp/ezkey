# Admin UI — API and Boundary Mappings

## Intent

This document describes how the Admin UI maps its internal state and user actions onto the Admin API contract. It is a **boundary document**: the left side is the UI (components, forms, state), the right side is the Admin API (endpoints, DTOs, problem types).

Representative mappings are listed below; additional mappings can be added using the [mapping matrix template](../../templates/mapping-matrix.template.md).

## Mapping Index

| ID | Scope | Direction | Status |
|----|-------|-----------|--------|
| `M-admin-auth` | Admin UI ↔ Admin API passwordless auth | bidirectional | `implemented` |
| `M-integrations` | Admin UI ↔ Admin API integrations | bidirectional | `implemented` |
| `M-admins` | Admin UI ↔ Admin API administrators list/detail | bidirectional | `implemented` |

## `M-admin-auth` — Passwordless Authentication

### Intent

Translate UI login state (username, challenge toggle, countdown) into Admin API requests, and Admin API responses into session state and UI states.

### Boundary

- **Left side.** Login form and `AuthProvider` in Admin UI.
- **Right side.** Admin API passwordless endpoints under `/api/v1/admin/auth/`.
- **Direction.** Bidirectional.
- **Trigger.** Operator submits login form.

### Reference Artifacts

- Admin API endpoints: [`../../../docs/ENDPOINT.md#admin-authentication-passwordless-only`](../../../docs/ENDPOINT.md).
- OpenAPI: [`../../../specs/admin-api/openapi-spec.json`](../../../specs/admin-api/openapi-spec.json) under `/admin/auth/login`, `/admin/auth/passwordless-wait`, `/admin/auth/logout`, `/admin/auth/me`.

### Field Mapping

#### Login request

| UI field | Admin API field | Transformation | Required | Notes |
|----------|-----------------|----------------|----------|-------|
| `usernameInput` | `username` | trim | yes | — |
| `challengeToggle` | `challengeRequested` | boolean | yes | Controls two-call vs single-call mode. |
| Always `true` | header `X-Non-Blocking` | constant | yes | Enforced by `api-client` when `nonBlocking: true`. |

#### Login response

| Admin API field | UI state | Transformation | Notes |
|-----------------|----------|----------------|-------|
| `authAttemptId` | `loginPending.authAttemptId` | identity | — |
| `expiresAt` | `loginPending.expiresAt` | parse as UTC | Drives the countdown via `formatCountdown`. |
| `challengeCode` | `loginPending.challengeDisplay` | `formatChallengeCode` | Zero-padded to 2 digits. |
| `status = "pending"` | UI state `awaiting-device` | enum | — |
| `status = success + token` | `AuthSession` | build session object | Stored in `sessionStorage` or relies on cookie. |

### Error Mapping

Errors arrive as RFC 9457 Problem Details. UI translates them through `getTranslatedApiError` against the `errors` namespace:

| Problem `type` suffix | i18n key | UI behavior |
|-----------------------|----------|-------------|
| `authentication.auth-rejected` | `errors.authentication.auth-rejected` | Inline alert; allow retry. |
| `authentication.auth-expired` | `errors.authentication.auth-expired` | Inline alert; reset form. |
| `authentication.auth-timeout` | `errors.authentication.auth-timeout` | Inline alert; allow retry. |
| `authentication.invalid-signature` | `errors.authentication.invalid-signature` | Inline alert; allow retry. |

Rate-limit responses (HTTP 429) are handled separately; the UI surfaces a friendly message with the `Retry-After` value when provided.

### Lifecycle Coupling

- **Spec version.** The UI targets the current Admin API OpenAPI spec regenerated by `scripts/update-specs.sh`.
- **Compatibility policy.** Contract changes require a coordinated backend + UI update and a refresh of the generated client.

## `M-integrations` — Integrations Management

### Intent

Translate integration list/create/retire/delete UI actions into Admin API calls, and Admin API responses into list and detail views.

### Boundary

- **Left side.** Integrations list page, Integration detail page, Create dialog.
- **Right side.** Admin API endpoints under `/api/v1/integrations`.
- **Direction.** Bidirectional.
- **Trigger.** Operator navigation or action.

### Reference Artifacts

- Admin API endpoints: [`../../../docs/ENDPOINT.md`](../../../docs/ENDPOINT.md) (Search Integrations, Integration retirement and deletion).
- OpenAPI: [`../../../specs/admin-api/openapi-spec.json`](../../../specs/admin-api/openapi-spec.json) under `/integrations`.

### Field Mapping — Create request

| UI field | Admin API field | Transformation | Required | Notes |
|----------|-----------------|----------------|----------|-------|
| `name` | `integrationName` | trim | yes | Uniqueness enforced server-side. |
| `description` | `integrationDescription` | trim, nullable | no | — |
| `tenantId` (Global Admin only) | `tenantId` | identity | conditional | Global Admin must select tenant when not scoped already. |

### Field Mapping — List response (per row)

| Admin API field | UI column | Notes |
|-----------------|-----------|-------|
| `id` | ID (sortable) | — |
| `integrationName` | Name | — |
| `lifecycleStatus` | Status badge | Badge shape from `feature/` components. |
| `active` (derived) | Compatibility column | Temporary during lifecycle migration. |
| `createdAt` | Created (sortable) | Rendered via `formatDate`. |

### Field Mapping — Retire / Delete actions

| UI input | Admin API | Transformation | Notes |
|----------|-----------|----------------|-------|
| `reason` | query param `reason` | trim, URL-encoded | Required by server; UI enforces min 10 chars. |

### Decision Table — Available actions

| UI condition | Retire button | Delete button |
|--------------|---------------|---------------|
| `lifecycleStatus = ACTIVE`, not system integration | visible | hidden |
| `lifecycleStatus = RETIRED`, zero enrollments | hidden | visible |
| `lifecycleStatus = RETIRED`, enrollments remain | hidden | disabled with helper tooltip |
| System integration | hidden | hidden |

### Constraints and Invariants

- The UI never attempts to cascade state changes on its own; retirement of children happens server-side.
- Reason strings are enforced at **≥ 10 characters** in the UI even though the server also validates.

### Error Mapping

- `409 Conflict` — shown as a warning alert; for delete on retired integration with remaining enrollments, the UI hints that enrollments must be handled first.
- `400 Bad Request` — inline alert with translated or server-provided message.

### Lifecycle Coupling

- **Spec version.** Aligned with the current OpenAPI spec.
- **Compatibility policy.** The `active` boolean is deprecated compatibility data; UI avoids relying on it where `lifecycleStatus` is available.

## `M-admins` — Administrators List and Detail

### Intent

Expose a legible, role-aware view of administrators so operators can triage scope (especially **which tenant** for tenant-scoped admins when acting as Global Admin), status, recency (`lastLoginAt`), and next actions (credentials, deactivate) without overloading the paginated table.

### Boundary

- **Left side.** `AdminsPage` and tenant detail administrators subsection (`tenant-detail.tsx`); detail dialog uses `AdminDetailDialog` patterns (Orval `listAdmins`, `getAdminById`, mutations).
- **Right side.** `GET /api/v1/admins`, `GET /api/v1/admins/{id}`, and related provisioning endpoints under `/api/v1/admins`.
- **Direction.** Bidirectional.
- **Trigger.** Operator opens Administrators or the tenant-scoped admin table; row click opens detail.

### Reference Artifacts

- Admin API: [`../../../docs/ENDPOINT.md`](../../../docs/ENDPOINT.md) (List / Get Administrator).
- OpenAPI: [`../../../specs/admin-api/openapi-spec.json`](../../../specs/admin-api/openapi-spec.json) — `AdminResponseDto` includes `tenantId`, `tenantName`, lifecycle and operational fields.

### Field Mapping — List row (Global Admin)

| Admin API field | UI column | Notes |
|-----------------|-----------|-------|
| `username` | Username | Sortable (`sort=username`). |
| `firstName` / `lastName` | Name | Display-only composite. |
| `email` | Email | |
| `tenantName` / `tenantId` | Tenant | Platform label for `GLOBAL_ADMIN`; link to tenant detail when `tenantId` present; fallback label if name missing. |
| `adminType` | Type | Badge; sortable. |
| `active` / `lifecycleStatus` / `operational` | Status | Badges + tooltips (pending activation, tenant inactive warning). |
| `lastLoginAt` | Last login | Relative + absolute; not sortable unless backend adds sort field. |
| `createdAt` | Created | Sortable. |
| — | Actions | Credentials when onboarding exists; Deactivate for Global Admin when active. |

### Field Mapping — List row (Tenant Admin)

Same as above **except** the **Tenant** column is omitted (redundant with tenant-scoped token).

### Field Mapping — Detail dialog

All non-sensitive `AdminResponseDto` fields; **Tenant** row shows `tenantName` with ID when available. Expandable related entities unchanged.

### Constraints and Invariants

- Pagination sort is **server-side**; list columns with `sortKey` must match backend `Pageable` property names.
- `tenantName` is denormalized for operator clarity; API remains authoritative for `tenantId`.
