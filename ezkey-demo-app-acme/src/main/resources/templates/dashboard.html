HOW THIS LOGIN WORKS

This demo application uses backend-side authentication. The server securely communicates with the EZKey Admin API using API Key Machine-to-Machine (M2M) authentication. All authentication logic runs server-side, ensuring tokens and credentials never reach the browser.

AUTHENTICATION FLOW

1 User enters username
→
2 Backend looks up enrollmentId
→
3 Server calls Admin API (API Key auth)
→
4 Wait for device approval
→
5 Issue authentication token/session

Use case: New applications or passwordless-first approach

Note: After successful authentication, your application typically issues a token (OAuth2, JWT, etc.) for session management. The implementation shown in this demo uses HTTP sessions, but token-based authentication is the most common approach in production.
