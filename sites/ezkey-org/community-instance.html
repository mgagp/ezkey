Ezkey is a product in alpha. The product site stays on ezkey.org. A maintained community instance runs on ezkey.online so evaluators can try the live stack without claiming a production offering.

Honesty bounds. Alpha is not a production SLA. Ezkey is not Duo / Okta / Keycloak parity. Ezkey is not WebAuthn / FIDO2 / passkey equivalence. The default runtime profile on the community host is integrity; base is an opt-in profile for limited claims — not an “eval-by-default” posture.

Who this is for, and how to request access

Direct invitations come first, aimed at specific profiles (engineering, product, specialized press).

Instant community access (limited daily slots): when enabled on the community instance, you can request a workspace immediately and receive a one-time activation code on the spot — no email required for that path. Slots are capped daily; when capacity is reached, try again later or use the email option below. French signup page.

Were you not invited but still want reviewed access? Email info@ezkey.org with a few sentences: who you are and what you want to validate. Access is not open to everyone: capacity is small and each request is reviewed; a reply is not guaranteed.

What you can use on ezkey.online

An all-in-one deployment meant for low volume and evaluation — not for load or the assurances of a production environment.

  • Ezkey Demo Device — simulated phone (public GitHub project) to stand in for the mobile app during evaluation: github.com/mgagp/ezkey-demo-device
  • Ezkey mobile app (Android) — early-adopter preview; still in limited internal testing and not the default path for anonymous evaluators.
  • Administration (tenant scope) — admin-ui.ezkey.online
  • Acme integration demo — demo-acme.ezkey.online
  • Admin API — admin-api.ezkey.online (and parallel Auth / Integration API hostnames on the same domain when you need them for tooling)

Android only in this milestone. iOS: no release date announced.

The mobile app does not yet have the full hardening expected of a shipping production release. The Android reference path has already strengthened local secret storage, but broader operational hardening still remains incomplete. App-open locking (biometrics or an equivalent strong mechanism, with control levels still to be specified) is planned on the roadmap; if it is missing or only partial on the community instance, treat that as a transitional state, not the final model.

Access: activation code and tenant administrator role

After a request is accepted (or you are invited), an activation code is sent by email; in practice, allow up to about two business days. The instant signup path returns the code immediately when daily slots are available.

Ezkey supports other enrollment paths in the ecosystem (including QR and recovery); here, the documented path is the activation code.

Administration has two levels: global (whole instance) and tenant (one organization). On the community instance, you act as a tenant administrator — enough for the Acme demo, enrollments, and authentication with the mobile app or Demo Device.
