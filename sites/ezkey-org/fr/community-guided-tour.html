Parcours invité

Parcours guidé communautaire : cycle complet jusqu’à la connexion avec l’app démo Acme

Une succession d’étapes admin, mobile et démo pour juger Ezkey sur un scénario bout-en-bout.

Public visé : personnes ayant accès à l’instance communautaire ezkey.online, à l’aise avec une UI technique — pas un grand public novice.

Avant de commencer

  • Votre code d’activation, issu de l’inscription instantanée (affiché une seule fois) ou reçu par courriel.
  • L’Admin UI sur admin-ui.ezkey.online.
  • Un téléphone : l’app mobile Ezkey, ou le Demo Device exécuté en local.
  • Une deuxième fenêtre de navigateur (navigation privée ou profil distinct) pour la démo Acme.

Ezkey est en alpha ; ses limites sont décrites une seule fois, sur la page de l’instance communautaire.

Objectif de ce guide

Ce parcours s’adresse à une personne ayant accès à l’instance communautaire qui souhaite explorer Ezkey : profil technique (collègue informaticien, équipe produit ou sécurité, journaliste spécialisé, etc.).

Le but est de faire vivre une expérience Ezkey de bout en bout, du premier contact avec la console jusqu’à une authentification réussie via l’application mobile, en s’appuyant sur une application de démonstration intégrée à l’instance communautaire ezkey.online. Les figures reprennent chaque étape numérotée. Une fois les étapes assimilées, prenez quelques minutes pour le tableau de bord du tenant dans l’Admin UI ; nous y revenons en fin de parcours.

Pas d’app mobile Ezkey ? Utilisez le Demo Device

L’application mobile Ezkey est encore en test interne limité et n’est en général pas accessible aux évaluateurs anonymes. En attendant une publication mobile publique, vous pouvez suivre ce parcours avec l’Ezkey Demo Device, un téléphone simulé autonome, publié sur GitHub et exécutable en local : github.com/mgagp/ezkey-demo-device.

  • Lancez-le avec Docker (voir le README du dépôt) ; par défaut il cible l’Auth API communautaire (auth-api.ezkey.online) et s’ouvre sur localhost:3080.
  • Il reprend la même cryptographie d’enrôlement et d’approbation que le client mobile, à des fins de démonstration.
  • C’est un outil d’assistance à la démo, pas un logiciel de production. Il n’offre pas les protections matérielles d’un vrai téléphone, en particulier le Secure Storage et le StrongBox (stockage de clés soutenu par le matériel Android) que l’app mobile est conçue pour utiliser.

Dans la suite de ce guide, chaque mention de « app mobile » vise aussi le Demo Device comme substitut pratique sur l’instance communautaire pour les évaluateurs en libre-service.

  1. Activer l’accès Tenant AdminCode d’activation, puis association du téléphone depuis l’écran de connexion.
  2. Créer une intégrationLa première action métier dans l’Admin UI.
  3. Créer une clé d’API pour celle-ciConserver l’identifiant et le secret hors du navigateur.
  4. Enrôler le téléphoneScan du QR et défi à six chiffres.
  5. Donner la clé d’API à la démo AcmeDans une autre fenêtre de navigateur.
  6. Se connecter et approuver sur le téléphoneSaisir le défi à 2 chiffres, puis approuver pendant le compte à rebours.
  7. Session établieLa démo affiche un écran connecté : le parcours complet a réussi.

Pourquoi l’intégration avant la clé API (et où entre l’app démo)

L’Admin UI pilote l’organisation : intégrations, enrôlements, admins, etc. Pour qu’une application « réelle » parle aux services Ezkey, l’usage normal passe par un backend qui utilise l’Integration API et des clés d’API pour des flux machine-à-machine.

  • Une fois une intégration définie, votre interlocuteur automatique, c’est l’application intégrée, pas seulement les écrans de l’Admin UI.
  • Sur l’instance communautaire, l’app démo Acme sur demo-acme.ezkey.online/login joue le rôle d’application intégrée, pour éprouver le cycle sans coder une appli complète tout de suite.
  • Un SDK Java fait partie du projet (la démo s’appuie dessus). Publication et disponibilité suivent le calendrier décrit sur ezkey.org.

1Activer l’accès Tenant Admin (code d’activation + mobile)

Ouvrir l’Admin UI sur admin-ui.ezkey.online et atteindre l’écran de connexion.

  1. Saisir le code d’activation reçu.
  2. Suivre le flux pour associer le téléphone : scanner le QR avec l’app mobile Ezkey ou le Demo Device (localhost:3080) et compléter les étapes à l’écran.

2Créer une intégration

Aller à la section Intégrations, puis créer une intégration avec les champs requis par l’instance communautaire (libellés, identifiants fonctionnels selon le formulaire).

3Créer une clé d’API pour cette intégration

Depuis le contexte de l’intégration :

  1. Lancer la création d’une clé d’API.
  2. Lorsque l’UI affiche l’identifiant et le secret (secrets machine-à-machine), les copier et les stocker hors du navigateur immédiatement ; la récupération ultérieure n’est en général plus possible telle quelle.

4Enrôlement : QR + défi à six chiffres

À la création de l’enrôlement, renseignez l’Identifiant utilisateur (userIdentifier) avec exactement le nom d’utilisateur que vous saisirez sur la démo Acme (par exemple alice). Le Nom n’est qu’un libellé d’affichage : il ne sert pas au login. Si l’Identifiant utilisateur est vide ou différent de ce nom d’utilisateur, le login démo échouera.

Lorsque le produit affiche le QR et le défi numérique (par ex. six chiffres), scannez puis saisissez le défi sur l’app mobile ou le Demo Device.

Alpha communautaire et déploiement durci. Sur ezkey.online, le QR et le défi numérique apparaissent souvent sur un même écran de l’Admin UI. Dans des environnements plus stricts, on répartit plutôt les canaux (par ex. QR par courriel, défi par SMS). L’instance communautaire n’intègre pas tous les connecteurs de messagerie ou d’opérateurs qu’on attendrait d’un produit mature.

5App démo Acme : saisir la clé API (autre navigateur)

Ouvrir une nouvelle fenêtre ou une navigation privée pour ne pas mélanger la session Tenant Admin et le rôle « appli intégrée ».

  1. Ouvrir demo-acme.ezkey.online/login dans cette session de navigateur séparée.
  2. Utiliser Configure API Key et saisir l’identifiant et le secret de la clé d’intégration depuis l’Admin UI (la démo ne les garde que pour cette session de navigateur).
  3. Enchaîner avec Login with EZKey une fois la clé appliquée.

Dans vos propres intégrations, traitez les clés comme des secrets côté serveur, pas comme quelque chose que les utilisateurs finaux collent dans une page.

6Login avec l’utilisateur d’enrôlement, approbation mobile

Au login, utilisez le même identifiant (la valeur de l’Identifiant utilisateur, pas le Nom).

La démo affiche un défi à 2 chiffres sur l’écran d’attente. Sur l’app mobile ou le Demo Device : ouvrir la demande en attente, saisir ce même défi à 2 chiffres, puis approuver dans la fenêtre affichée par la démo.

7Session établie côté démo

Après accord sur le téléphone, la démo doit passer à une vue de session active (pseudo-application), avec déconnexion disponible selon les écrans.

Ensuite : tableau de bord du tenant

Revenir sur le Tableau de bord du tenant dans l’Admin UI : il résume l’activité et renvoie vers les autres sections utilisées dans ce parcours.

Ce parcours n’épuise pas le produit ; il donne une succession fonctionnelle utile pour un invité qui veut juger Ezkey avant de se projeter.
