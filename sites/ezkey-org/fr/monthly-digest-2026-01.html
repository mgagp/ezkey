Admin d’abord en terminal — le pari TUI, consolidation doc et fondations plateforme

Un regard distillé sur janvier — une console admin texte construite comme la vraie surface opérateur, une consolidation documentaire pragmatique après un rythme de build effréné, et préparation JDK 25 / Spring Boot 4 à travers la stack.

En bref

Janvier a été un mois plateforme centré sur comment administrer Ezkey sans s’engager encore dans un stack UI web complet. Le fil dominant: un TUI Python interactif — tenants, intégrations, clés API, tentatives auth, journaux d’audit, clés de chiffrement, lots de re-chiffrement — construit comme l’outil d’administration retenu, pas comme couche d’inspection temporaire avant une console graphique. Le besoin d’interface opérateur était clair; un stack web classique avec React et son écosystème ne semblait pas prêt à être assumé. En parallèle, la stack a avancé sur JDK 25, préparation migration Spring Boot 4, hygiène des dépendances, et versioning Maven CI-friendly. L’API Crypto a gagné des endpoints encrypt/decrypt; les flux auth ont mûri avec codes challenge, annulation de tentatives, et sémantique reject/expired plus claire. Bootstrap Docker, health checks, et une application démo ACME ont facilité le démarrage de la stack. La documentation a connu une large consolidation — après un rythme effréné de plans séquentiels, parfois deux ou trois sessions à la fois, ayant produit un corpus tentaculaire — un rangement pragmatique court terme plutôt qu’un arrêt de livraison pour reset méthodologique complet. Tests fonctionnels et multi-tenant ont été élargis. Le mois se lit comme le choix du terminal comme admin, le durcissement plateforme, et l’apurement de dette doc avant que février n’ouvre la voie console graphique.

Documentation & méthodologie

Une consolidation large a retiré plans obsolètes et fusionné guides développement, jetons et tests — pas du ménage pour le ménage, mais une réponse pragmatique à un corpus documentaire devenu vite volumineux et désordonné sous sessions de build parallèles. De nouveaux écrits sont quand même arrivés: stratégie de partitionnement base de données, analyse mécanisme de synchronisation keyset, stratégie tests fonctionnels CLI, et configuration profils Spring. Collections Postman ont suivi l’API Crypto naissante. Gains méthodologiques reportés; la passe visait à restaurer la clarté sans freiner l’élan.

Hygiène de code

Migration JDK 25 déployée sur services et images Docker de base. Travail migration Spring Boot 4 démarré avec mises à jour gestion d’erreurs et configuration. Versions de dépendances mises à jour pour PMD, ZXing, Bucket4j, plugins Maven, et RestAssured. Versioning CI-friendly entré dans les POM Maven. Checkstyle ajusté pour compatibilité Google Java Format. THIRD-PARTY.txt rafraîchi.

Admin UI

Pas d’UI admin graphique ce mois-ci. L’administration devait passer par le TUI texte — première surface opérateur, et à l’époque celle retenue. Un stack UI web complet semblait encore un pari trop lourd tant que profondeur backend, crypto et opérabilité restaient prioritaires. Rétrospectivement, les limites d’une console texte pousseraient vers un admin React plus tard dans l’année; en janvier, le TUI était le plan, pas une marche intermédiaire.

Calme en janvier d’après l’activité Git sur cette fenêtre.

Backend & contrats d’API

Tentatives auth: annulation, support codes challenge, séparation DTO/mappers entre Admin et Auth APIs, et correctifs confusion reject/expired sur le parcours d’attente. L’API Crypto a ajouté endpoints encrypt et decrypt avec couverture Postman à jour. Contraintes d’unicité enrôlement pour enrollments vérifiés, avec plans et tests. Endpoints gestion tenant et specs OpenAPI rafraîchis. Export credentials bootstrap et configuration chiffrement par profil ont renforcé premier démarrage et stockage des clés.

Le reste, digne de mention

  • CLI / TUI: fil dominant du mois — TUI admin interactif avec écrans intégrations (modal filtre), journaux audit, tentatives auth, clés API, validation crypto, clés chiffrement, lots re-chiffrement, gestion tenants; support souris si disponible; utilitaires pagination; tests CLI et câblage entrypoint Docker; modales onboarding et création admin en fin de mois.
  • Démo & Docker: structure application démo ACME avec auth backend; fichiers config Docker et Windows; scripts stack PowerShell; health checks et ports management améliorés.
  • Tests: tests isolation multi-tenant, documentation tests fonctionnels et améliorations résilience, couverture intégration unicité enrôlement.

Janvier a parié sur le terminal comme console admin. Travail plateforme et contrats a suivi en dessous. La voie admin graphique — d’abord cadrée tenant UI, plus tard unifiée — s’ouvrirait en février une fois la surface texte ayant prouvé le modèle d’exploitation mais aussi son plafond pour opérateurs non développeurs.
